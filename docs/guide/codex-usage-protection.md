# Codex 额度保护

[English](codex-usage-protection.en.md)

在 **Settings → General → Codex 额度保护** 配置订阅额度使用上限及付费 Credits 开关。这是所有 Codex OAuth 连接的全局策略，旧配置升级后也默认生效。

- **订阅额度使用上限**：默认 **98%**，接受大于 0 且不超过 100 的百分比。主窗口或次窗口任一个达到上限，就停止向该连接发送新的推理请求，并使用其他可用连接；没有替代连接时返回额度不可用。多个窗口各自等待 reset，短窗口恢复不会提前解除仍超限的长窗口。
- **允许使用付费 Credits**：默认**关闭**。显式开启后可超过上述阈值；订阅耗尽时，只有上游报告有可用或无限 Credits 才继续。上游的额外限额、消费上限及实际拒绝仍然有效。该开关不能指定上游对某一次请求使用哪种余额。
- **重置卡**：AutoReset 的临期重置券独立管理；开启付费 Credits 不会开启或消耗重置券。

Ferry 优先读取推理响应中的 Codex 主/次窗口用量、reset 时间和 Credits 响应头，在成功、流式及错误响应中更新状态。字段缺失或格式不正确不会被当作额度归零。并发响应乱序时，同一 reset 窗口中较低的用量不会覆盖已经观察到的较高用量。

首次调用会读取上游 usage。后续请求在发送前使用最近 30 秒内的有效额度证据；过期、缺失或窗口跨过 reset 时重新查询。完整 usage 至少每 5 分钟核对一次，以刷新响应头未覆盖的限制。无法获取有效额度时拒绝发送推理请求，不用试探性推理确认是否还有付费额度。重启后的持久缓存仅用于显示，不能替代本次进程的首次查询。

这是一项基于上游已报告用量的路由保护，不是上游硬性消费限额。请求已发送、并发调用、其他客户端共用账号以及上游记账延迟都可能导致实际用量超过阈值；98% 默认值提供余量，但不能承诺零超额。

管理 API 示例：

```json
{
  "codex_usage_protection": {
    "max_used_percent": 98,
    "allow_credits": false
  }
}
```

通过已认证的 `PATCH /api/settings` 保存，并用 `GET /api/settings` 回读。配置持久化到控制库，修改后重新评估现有额度冷却；未改变实际上游余额。

Codex 更新或模型同步发现可见的新模型时，默认创建对应的同名逻辑模型，已有人工路由保持不变。定时同步被关闭时，需使用渠道的 **Sync now**；只读目录预览不发布配置。详见[模型同步](../provider-model-sync.md)。
