# 配置说明

客户端只需要一个模型入口。Ferry 的配置负责把这个入口接到合适的账号、模型和线路上，并决定何时等待、何时换路。下面先说明这些对象如何配合，再说明启动、身份和数据。

## 模型如何路由

| 概念 | 含义 |
| --- | --- |
| Provider | 上游服务及其公共设置 |
| Connection | 一个具体连接的凭据、协议、模型与运行限制 |
| 上游模型 | 供应商接受的准确模型 ID |
| Logical Model | 客户端使用的稳定模型名及其路由配置 |
| Route / Override | 默认选路顺序与匹配特定条件的覆盖规则 |

客户端请求一个 Logical Model。网关依据路由、协议、能力、凭据和运行状态选择 Connection，再调用对应上游模型。例如，客户端始终请求你创建的 `work`，Ferry 根据配置使用首选或备用上游；`work` 不是内置模型。

创建 Provider 后，检查它对应的模型与默认路由。自建逻辑模型先配置有效路由，再启用。模型名相同不保证能力相同，目录中出现的模型也不一定能处理工具、流式或图片请求。

配置编辑先形成草稿，校验、模拟并审阅后再应用。API 写入携带要求的 revision，发生冲突时重新读取当前配置。逐步配置备用线路、分时规则和首输出等待上限，见[长任务指南](long-tasks.md)。

## 启动配置与运行配置

`config.example.yaml` 是空库首次启动的最小配置，内容与源码中的示例一致：

```yaml
server:
  data_dir: ./data
  management_addr: 127.0.0.1:7900
  proxy_addr: 127.0.0.1:7890
  timezone: UTC
  log_retention_days: 30
```

通过 `-config` 导入一次后，SQLite 保存运行配置。修改 YAML 不会更新现有实例；日常变更使用控制台或管理 API。`-data-dir` 指定本次进程使用的数据目录，启动前确认没有指向另一个实例的数据。

管理端和推理端独立监听。Compose 示例在容器内使用 7900／7890，在宿主机上仅发布 `127.0.0.1:17910`／`127.0.0.1:17810`。容器里的 `localhost` 指向容器自身，不能直接代替宿主机或其他服务地址。

## 两种 Key 与管理员

| 身份 | 用途 | 创建位置 |
| --- | --- | --- |
| 管理员会话 | 控制台和管理员操作，写入受 CSRF 保护 | 首次初始化／登录 |
| Management Token | Agent 或自动化调用 `/api/*`；高风险操作由独立开关控制 | Settings → Security |
| 推理 API Key | 客户端调用 `/v1/*`，按 Key 约束模型、协议和配额 | API Keys |

两类 Key 不能互换。给不同客户端或自动化分别创建身份，按需要收窄权限。Token 安装或读取成功不意味着获得高风险写权限。

## 凭据与账号

上游 API Key 和 OAuth 凭据由本机 secret store 保存；配置通常引用凭据，而不是直接携带令牌。原生账号引用形如 `native-oauth:<driver>:<account>`。完成登录与保存 Provider 是两个动作，登录成功也不代表模型能力已验证。

SQLite 和备份可能包含可读取的凭据。文件权限是访问控制，不是加密。Ferry 不依赖特定秘密管理服务；使用 Agent 客户端时，可以通过自己的秘密管理器或进程环境提供访问凭据。

## 数据目录

| 文件 | 主要内容 |
| --- | --- |
| `control.db` | 管理身份、配置版本、客户端 Key、上游凭据 |
| `ledger.db` | 请求、尝试、用量、成本和诊断记录 |
| `conversation.db` | 会话绑定及续轮状态 |

一个实例使用一个本地目录。备份时保留三类数据库的一致性，使用[内置备份和恢复命令](operations.md)，不要把活动数据库直接复制为备份。
