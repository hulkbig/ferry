# Hermes 用 ChatGPT 订阅

[English](hermes.en.md) · [Docker 安装](docker.md)

把已有账号接到 Ferry，给 Hermes 配一组线路。一个账号限流了，就按规则等待或换另一个，不用你来回切。

## 先在 Ferry 配好线路

1. 在 **渠道（Providers）** 添加自己的账号或 API。ChatGPT 账号按 Codex OAuth 接入；其他订阅只使用 Ferry 已支持的登录方式。保存并启用对应 Provider。
2. 在 **模型与路由（Models & Routing）** 建立逻辑模型，例如 `work`。将支持相应协议和能力的账号、上游模型安排为首选和备用步骤。`work` 是示例名称，不是内置模型。
3. 配置并发、等待与恢复条件。先校验和模拟路由，再应用配置。不要只因为模型名称相同，就假定所有账号都支持工具或多轮续接。
4. 创建只允许访问该模型的**推理 API Key**，供 Hermes 使用。不要把上游账号凭据或 Management Token 填进客户端。

在同一路由步骤内，Ferry 会综合协议与能力匹配、已知配额压力、近期限流、健康状态和并发情况选择连接。耗尽且尚未重置的已知配额窗口会影响可用性；配额未知不按无限额度处理。跨步骤是否切换，仍取决于你设置的路由和恢复条件。

## 在 Hermes 选择 Ferry

运行：

```sh
hermes model
```

按 Hermes 当前版本的提示选择自定义 OpenAI 兼容端点，填写：

| 设置 | 内容 |
| --- | --- |
| Base URL | 同机 Docker 示例：`http://localhost:17810/v1`；远程实例填写你已配置的 HTTPS 推理入口 |
| API Key | 刚创建的 Ferry 推理 Key |
| Model | `work`，或你实际创建的逻辑模型名 |

这是 Hermes 官方支持的自定义端点方式，见[官方供应商文档](https://hermes-agent.nousresearch.com/docs/integrations/providers)。如果 Hermes 与 Ferry 位于不同容器，`localhost` 指向当前容器，需要使用实际可达的服务地址。

## 跑一个真实任务

先完成简单对话，再运行包含工具调用和工具结果续轮的任务。在 Ferry 的 **请求（Requests）** 中核对实际选择的连接、恢复原因和最终结果；通过 **用量与费用（Usage & Billing）** 查看记录。

接入方式已按 Hermes 官方资料与 Ferry 路由实现核对；本文不代表已逐一实测所有 Hermes 版本、订阅或模型组合。模拟路由不调用上游，不能替代真实任务验收。

## 额度怎么算

Ferry 不把不同计划的额度合成一个余额，也不会扩大供应商授权。它使用你已接入且当前可用的线路，减少你在账号之间手动切换。配额信息以各渠道实际提供的数据为准；上游权限、重置周期和用量限制仍然有效。

恢复有时间与次数预算，客户端取消会结束等待。已经提交可见输出后，不拼接另一条模型流。备用 API 可能按调用计费；将其放入路由前确认费用和使用条件。更多配置见[长任务指南](long-tasks.md)。
