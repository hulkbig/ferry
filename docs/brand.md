# Ferry 品牌与文案

## 名字与主张

项目名为 **Ferry**，中文名为 **渡口**。中文首页使用“Ferry 渡口”，控制台字标使用“Ferry”。渡口连接两岸；Ferry 连接你使用的 Agent 与不断变化的模型和线路，让工作有路可走。

| 用途 | 中文 | English |
| --- | --- | --- |
| 产品简介 | 为 AI Agent 长任务设计的自托管网关 | A self-hosted gateway built for long-running AI agent tasks |
| 首页主张 | 少守着重试，让 AI 继续干活。 | Less time retrying. More time for your AI to work. |
| 一句话说明 | 用一个稳定模型入口，处理上游选路、临时故障恢复与请求诊断，减少长任务中的人工介入。 | One stable model endpoint for routing, transient failure recovery and request diagnostics—with less manual intervention during long tasks. |
| 页面标题 | Ferry 控制台 | Ferry Console |

## 先讲用户为什么在意

Ferry 的故事从“我把任务交出去了，却还得回来换线路”开始。先说明它替用户接下了什么工作，再解释机制，最后给出下一步操作。

产品介绍按以下顺序展开。八字标题先讲清一个收益，正文再解释机制：

| 顺序 | 分类 | 标题 | 正文重点 |
| --- | --- | --- | --- |
| 1 | 任务连续性 | 限流等待，自动续接 | 在恢复窗口内保持请求等待，条件允许后继续响应 |
| 2 | 任务连续性 | 上游故障，自动接力 | 当前线路失败时，按策略选择可接手的备用线路 |
| 3 | 任务连续性 | 并发可控，高峰排队 | 控制请求节奏，超出容量按策略等待 |
| 4 | AI 自主使用 | AI 友好，自助运维 | Skill 与管理 API 是正式入口，AI 可直接诊断与受控变更 |
| 5 | AI 自主使用 | 能力实测，按需匹配 | 依据选定端点与模型的实际能力选路 |
| 6 | 灵活接入 | 入口不变，模型可换 | 上游配置变化，客户端继续使用稳定模型名 |
| 7 | 灵活接入 | 三种协议，统一接入 | Chat、Responses、Messages 一等接入 |
| 8 | 透明排障 | 请求过程，有据可查 | 一次客户端请求下串起尝试、恢复与费用依据 |

单程序、SQLite、渠道数量和 Key 管理作为使用基础，在核心能力之后介绍。

## 写出值得试一试的理由

使用直接、温暖、有画面的语言。可以从“回来发现任务停在一次 429”这样的具体时刻写起，也可以邀请读者“为你的 Agent 配好第一条恢复路由”。每一段优势都落到实际动作或可检查的记录上。

| 写作场景 | 推荐表达 |
| --- | --- |
| 解释逻辑模型 | 上游换了，客户端仍用原来的模型名。 |
| 介绍恢复 | 遇到可恢复故障，先按策略等待或换路。 |
| 介绍能力证据 | 先确认这条线路能接住任务，再让它接手。 |
| 邀请贡献 | 带来一次可复现的中断，帮助下一个任务继续向前。 |

首页主张表达产品追求；正文说明当前机制。Thinking 是客户端可能显示的处理状态，不代表网关能让上游模型始终推理；并发控制不承诺账号不会被封禁。恢复条件、首输出超时需要配置，恢复有预算，流式输出提交后不换流。不要把这些能力写成“永不中断”“无限重试”或“任意客户端无损兼容”。引用验证结果时说明实际客户端、上游和版本，不把离线测试写成真实供应商验收。

README 负责让人看懂价值并开始使用；指南负责完成一个具体任务；参考文档负责准确描述字段与边界。技术说明保留必要细节，不给每一段都加宣传口号。

## 配图语言

采用抽象的软件科技视觉，以请求路径、等待、切换和受控管理为主体。不要把 Ferry 画成真实的船、码头或运输场景。保留现有 Logo，配图用途、语言版本与来源见[README 配图](assets/README.md)。

## 名称与技术标识

命令、Skill、容器服务和新发布产物使用小写 `ferry`，连接环境变量使用 `FERRY_` 前缀。保持一个名称，不另写 FerryAI 或 FerryAPI。界面继续使用模型、渠道、路由、Key 等功能名称。

沿用当前几何图标，来源见[图形资产说明](asset-provenance.md)。版权主体仍为 hulkbig；上游项目名称与版权声明保持原样。

当前 Go module 为本地标识 `ferry`。公开托管地址确定后，再统一设置远程 module 路径、导入与构建参数；本地目录名不属于产品名称。旧名称的兼容范围见[迁移说明](guide/migration.md)。

## 正式图标

主标采用两端相扣的几何造型，中间留白形成小写 f，表达 Agent 与模型的连接。主色为炭黑 `#242424`，深色背景使用 `#ffffff` 反白版；两版使用相同轮廓、透明背景、纯色填充，无渐变和阴影。

源文件为 `web/console/brand.svg` 与 `web/console/brand-reverse.svg`。浏览器使用 `favicon.svg`，按系统配色切换；控制台侧栏与登录页按控制台当前主题切换，包含手动覆盖。README 使用 picture 提供两版。造型来自项目自有设计稿的 04 相扣方案，颜色为六档灰度中的 02。
