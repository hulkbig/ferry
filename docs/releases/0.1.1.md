# Ferry 0.1.1

修复 Codex 用量因上游重置时间轻微漂移而停留在旧百分比的问题，并恢复相应额度保护。

Fix Codex usage remaining stale when the upstream reset deadline changes by a few seconds. The quota guard now receives the updated exhaustion state.

## 修复 / Fix

- 用量查询和推理响应头的重置时间相差不超过 60 秒时，视为同一窗口，保留较高用量和较晚的重置时间。例如旧数据为 57%，新数据为 100% 且重置时间提前 3 秒，现在会更新为 100%。
- 较低的并发观测不会重新开放已耗尽窗口；真正的新窗口和显式重置仍允许恢复。
- 回归测试覆盖正反向时钟漂移、旧／新窗口、缓存持久化，以及用量查询和响应头两条额度保护路径。

Nearby reset deadlines share the stricter usage observation. A lower concurrent reading cannot reopen an exhausted window. A new reset epoch and explicit resets continue to permit recovery.

## 安装与升级 / Install and upgrade

```sh
curl -fsSLo compose.yaml https://github.com/hulkbig/ferry/releases/download/v0.1.1/compose.yaml
docker compose up -d
```

Linux AMD64 / ARM64: `bighulk/ferry:0.1.1`。管理控制台 / Console: **http://localhost:17910**。

从 0.1.0 升级前先备份并验证恢复路径，替换 Compose 后运行上述启动命令。没有数据库格式变更。默认备份保留当前配置及恢复凭据；需要完整历史时显式使用 `-backup-history`。

Back up and verify recovery before upgrading from 0.1.0. Replace Compose and start the service. This patch does not change the database format. Default backups retain current configuration and recovery credentials; use `-backup-history` when migrating full history.
