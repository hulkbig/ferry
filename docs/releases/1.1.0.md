# Ferry 1.1.0

Docker quick setup now pulls a prebuilt image without a source build. Headless operation removes the management listener and optional background jobs, while request-path optimizations retain authentication, quotas, usage and decision traces.

Docker 快速安装统一直接拉取预构建镜像；新增无界面运行模式，继续保留鉴权、配额、用量和决策轨迹。原计划的 1.0.1 安装修复合并到本版，未另行发布 1.0.1。

## Fixed / 修复

- Default root and legacy Compose files no longer implicitly build. Quickstart and operations instructions use image-based installation; explicit developer overrides retain source builds. The legacy `/data` layout is preserved.
- 默认两条 Compose 路径不再隐式 build，快速开始与运维文档统一镜像安装。旧版 `/data` 布局保留，避免升级时误用新安装的 `/data/state`。
- Coalesce superseded queued live-request snapshots to reduce backlog growth. Final request records, usage, attempts and traces remain intact; transaction replay preserves ordering.
- 合并排队中已过时的进行中快照，保留最终记录和失败重放顺序。API Key 使用时间批处理仍等待持久提交，并保持单调性和错误传播。
- Avoid disabled debug-response serialization and share decoded JSON across standard Chat response inspection. Unknown-field diagnostics and nonstandard-content compatibility remain covered by differential tests.
- 调试捕获关闭时减少无用途序列化；Chat 内容与字段检查共用解析树，保留未知字段提示与异常内容兼容。

## Added / 新增

- `-headless` for the ordinary binary/image; `-tags headless` for a dedicated developer build without embedded console assets. No separate published headless-image tag is claimed.
- 新增 `deploy/compose.headless.yaml`，使用预构建镜像、只发布推理端口。先在普通模式配置账号与路由，再停机切换；两个实例不能共享同一 SQLite 数据目录。
- Bilingual performance/resource documentation, numerical CSV/JSON evidence, reproducible diagrams and isolated Mock/load tools.
- 中英文首页提供内存、CPU 对比图及测试方法；下载数据保留完整测量指标。

## Measured performance / 实测

64 KiB JSON: Ferry peak working set 34.5 MiB; CLIProxyAPI 67.5 MiB; sub2api with PostgreSQL/Redis 432.5 MiB. Peak CPU: Ferry 157.1%, CLIProxyAPI 151.2%, sub2api stack 406.3% (100% = one core). See [methodology](../guide/performance.en.md) for configuration and sampling.

64 KiB JSON 场景：Ferry 峰值工作集 34.5 MiB，CLIProxyAPI 67.5 MiB，sub2api（含 PostgreSQL/Redis）432.5 MiB。峰值 CPU：Ferry 157.1%、CLIProxyAPI 151.2%、sub2api 整套服务 406.3%（100% 为一个逻辑核）。[测试方法](../guide/performance.md)。

## Upgrade / 升级

Back up configuration and required history using the existing backup commands, pull the exact new image, drain requests and recreate the service using the existing data layout. Do not delete volumes. No database-format migration is introduced. A release rollback still requires the normal compatibility and restore checks; these notes do not promise automatic database rollback.

按既有流程备份配置与需要保留的历史，拉取准确版本镜像，排空请求后原位重建容器。不删除卷，不更改数据路径。本版不引入数据库格式迁移。无界面模式禁用自动额度重置、计划消息和其他可选后台任务，启用前核对是否依赖这些功能。

## Limits / 已知限制

The total asynchronous ledger queue remains unbounded; snapshot coalescing is not full overload backpressure. Configure ingress concurrency and waiting budgets. Existing quota/progress fixes are retained and regression-tested, not presented as newly introduced here.

异步账本总队列仍无硬上限，快照合并不等于完整背压。已有额度与进度修复继续保留，不重复宣称为本版新增。
