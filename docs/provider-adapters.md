# 内置渠道适配边界

Ferry 的基本运行不依赖 CLIProxyAPI、Magpie、Bun 或外部插件进程。新增渠道优先复用现有协议，只把有证据的厂商差异放到内置适配器中。这些接口位于 `internal/`，随 Ferry 源码一起编译，不是供外部二进制加载的稳定 SDK。

## 职责

| 接口 | 负责 | 不负责 |
| --- | --- | --- |
| `nativeauth.Driver` | 登录、完成授权、刷新凭据 | 凭据落盘、刷新互斥、请求调度 |
| `nativeauth.EndpointBinding` | 从已保存的账号解析端点与协议；不执行网络 I/O | 根据任意请求地址发送凭据 |
| `nativeauth.EndpointValidator` | 不读取凭据的端点配置校验 | 证明账号或模型可以调用 |
| `nativeauth.NonRotatingRefresher` | 明确声明未知刷新结果能否安全重试 | 把缺少 refresh token 推断成安全 |
| `egress.Caller`、`Preparer`、`DetailedPreparer` | 协议编码、流式解码、兼容预检与诊断 | 选择账号、决定重试预算、记账 |
| `egress.ProviderAdapter` | 对已识别端点的请求做有限规范化 | 登录、网络请求、调度、改变模型能力事实 |

认证管理器继续拥有凭据存储、账号锁和未知刷新结果处理。动态端点在刷新前后重新核对，传输层继续限制凭据目的地。命名接口沿用了原来的可选方法合同，现有驱动不需要实现不适用的扩展。

协议适配器继续拥有响应事件和终态语义。ProviderAdapter 不解析流，不合成工具执行结果，也不将异常流标记为成功。请求取消、首个有效输出的提交边界、重试、并发槽和账本仍由核心负责。

## 请求规范化

`NormalizeRequest(protocol, native, body)` 接受协议编码后的请求，返回规范化结果或错误。实现不得原地修改输入字节；错误必须传回预检或调用方，不能在失败后静默发送旧请求。

选择规则使用最终端点地址，包括 FullURL 的优先级，而非用户填写的渠道名称。未知主机不套用已知厂商规则。新增规则需同时验证原生直通和跨协议编码路径，且不得修改 schema 的 `default`、`examples` 等普通 JSON 数据。

当前规则覆盖 Kimi 可无歧义推导的 enum 类型、DeepSeek 独立 NUL 正则转义以及已有 Zhipu 原生 Chat 规范化。Kimi 混合类型不强行猜测；DeepSeek 规则不把字面反斜杠或数字转义当作 NUL。规则来源和支持边界见[渠道支持范围](provider-channel-coverage.md)与[协议完整性](protocol-fidelity.md)。

## 新增规则的验收

1. 记录官方文档或官方客户端的准确来源。第三方项目参考须记录提交号；npm 包还需核对维护方和固定版本。
2. 指定端点、协议、触发字段、输出变化及是否有损。不得从模型名称推断能力。
3. 用离线用例证明正常转换、畸形输入、相似但不匹配的端点、无关字段保留及错误传播。
4. 涉及响应语义时，覆盖普通、流式、工具结果续轮和取消。协议实现通过不等于真实端点支持；实际验证记录必须独立保存。
5. 新增能力仍通过模型/端点声明和探测证据进入路由。不能因为适配器会编码某个字段，就给所有兼容渠道自动勾选支持。

## 外部插件的边界

当前没有动态库装载、npm 插件安装或任意脚本执行入口。CLIProxyAPI 的能力划分和 Magpie 的渠道宿主提供设计参考，不直接成为 Ferry 的依赖。

如果未来需要独立分发渠道，实现外部宿主之前还需定义版本协商、权限与凭据作用域、流式背压、取消、进程崩溃、旧流排空和升级恢复合同。外部插件、Gemini 原生签名桥和 Responses 高级工具多轮映射是独立工作，不能从本次内置接口整理推导为已经支持。
